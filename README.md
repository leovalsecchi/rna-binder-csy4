# De novo protein binders to the Csy4 crRNA hairpin — pipeline archive

Code archive for the computational arm of the thesis *De novo design of RNA-binding
proteins targeting the Csy4 crRNA hairpin*: five generative design stacks, three
structure re-prediction backends, the metric suite computed over them, and the filter
cascade that reduced 6,992,515 designs to the 12,000-member library that went to
synthesis.

This is an **as-run snapshot**, not a reconstructed history. The pipeline was developed
directly on a cluster filesystem without version control, so there is no commit series
to publish; the snapshot was taken from the production tree at the computational data
freeze and tagged once. What is here is what ran.

## What this archive can and cannot do

It documents the pipeline exactly: every configuration file is the production file, not
a reconstruction. Campaign submission overrode **only** scheduler fields
(partition, nodelist, GRES, walltime) plus the per-job HalluDesign seed, so
`configs/*/default.yaml` can be cited directly as the parameter set that ran.

It will **not** regenerate the dataset, and no amount of care with this code would
make it do so:

- **RFdiffusion3** runs with `seed: null` — unset.
- **BoltzGen** and **BoltzDesign1** expose no seed argument at all.
- **LigandMPNN** is pinned at a constant `seed: 42` across all four stacks that use it,
  so within one backbone the ten sampled sequences are fixed, but the backbone handed
  to it is not.
- **HalluDesign** is seeded per job, and its initial 80-mer is reproducible from that
  seed, but its vendored LigandMPNN wrapper draws a fresh seed from OS entropy and
  overwrites the global torch/numpy/random state before sequence sampling
  (`halludesign_upgrade/LigandMPNN/package.py`). Everything after that point diverges
  between runs.

**No stack in this work is seed-reproducible at the level of an individual design.**
Aggregate distributions are reproducible; individual designs are not. Where a specific
design matters, use the archived coordinates rather than attempting to regenerate it.

## Layout

```
pipeline/src/        rna_binder package: pipelines, io, filters, analysis, refolders
pipeline/scripts/    collection, cleaning, metric computation, aggregation, selection
pipeline/pylibs/     helper libraries imported by the above
configs/             production YAML for all five stacks and three refold backends
ops/                 Slurm submission, refold drivers, watchers, aggregation, loops
analysis/            plotting suite, campaign kit
patches/             modifications applied to third-party tools (see below)
docs/                design and findings notes cited by the Methods chapter
provenance/          Supplementary Table S1, deviation timeline, build script
```

Two directories deliberately absent:

- `code/envs/` (~724k lines) — the pip environment. Pinned by version in
  `provenance/versions.tsv` instead.
- `code/pylibs_dockq/` (~599k lines) — vendored DockQ 2.1.3. Pinned by version and
  dependency set; the upstream release is public.

`.bak_pre_*` files are kept on purpose. Several are the only surviving record of
pre-fix behaviour for the changes listed in `provenance/deviations.md`, and designs
produced before those dates were generated by the `.bak` variant, not the live file.

## Patches to third-party tools

Three of the five stacks did not run as distributed. The patches under `patches/` are
part of the method, not packaging detail — results are not comparable to upstream
behaviour without them. See `provenance/deviations.md` for what each one changes and
which designs it affects.

## Containers

Model execution was containerised (`apptainer exec --nv`). Images are 3.5–15.7 GB and
are not in this repository; they are deposited separately and cited by sha256 digest in
`provenance/S1.md`. All nine production images have been hashed.

Two components have no recoverable version. The Protenix distribution bundled into
`af3_protenix_esm.sif` carries no version string anywhere, and `esmc.sif` was built from
a `docker-archive` tar that no longer exists, so its build recipe is gone — for both,
the image digest is the only identifier. `provenance/container_recipes/` holds the build
recipes that do survive.

## Data

Design coordinates, metric tables and the selection outputs live on the ETH Euler
cluster under `/cluster/work/wicky/lvalsecchi/rna_binder/`, mirrored nightly to the
group NAS. The assembled metric masters are 12–15 GB and are not deposited in full;
the deposited reduction is the gated design set, the 12,000-member library and the
ordered hits. See `provenance/data_availability.md`.

## Reproducing the analysis layer

The metric and selection code *is* deterministic given the archived structures, and
that is the part worth re-running. `provenance/build_archive.sh` refreshes this tree
from the production source.
